# Output Folder Structure

This document explains the layout of the Publications vault generated by the organiser.

---

## Overview

```
Publications/                                 ← vault root (output_root in config)
│
├── 00_Inbox_Review/                          Papers below confidence threshold
├── 01_Renamed_PDFs_By_Research_Theme/        All imported PDFs, renamed
├── 02_Obsidian_Notes/                        All Markdown notes
├── 03_New_Papers_Inbox/                      Incremental import staging area
├── 90_Metadata/                              Logs and catalogs
└── 99_Duplicates_or_Unclear/                 Canonical-name collisions
```

---

## 01_Renamed_PDFs_By_Research_Theme

PDFs are grouped by **primary research theme → publication year**.

```
01_Renamed_PDFs_By_Research_Theme/
├── Design_and_Fabrication/
│   ├── 2024/
│   │   └── 2024-ICRA-Tactile-Sensor-Fabrication-Zhang.pdf
│   └── 2023/
│       └── 2023-RAL-Gel-Sensor-Design-Li.pdf
├── Multimodal_Perception/
│   └── 2025/
│       └── 2025-IROS-Depth-Estimation-Benchmark-Wang.pdf
├── Robot_Learning/
│   └── ...
└── Human_Robot_Interaction/
    └── ...
```

**Canonical filename format:**
```
YEAR-VENUE-Keyword1-Keyword2-Keyword3-FirstAuthor.pdf
```

- `YEAR` — 4-digit publication year, or `XXXX` if unknown
- `VENUE` — short venue code (ICRA, IROS, RAL, TASE, ...), or `Unknown-Venue`
- `Keyword1-3` — top meaningful words from the paper title
- `FirstAuthor` — first author surname

Papers below the confidence threshold (default: 0.50) go to `00_Inbox_Review/` instead.

## 02_Obsidian_Notes

All Markdown notes. Linked to PDFs using vault-relative paths — no absolute paths.

```
02_Obsidian_Notes/
├── Papers/                           Main note per paper (YAML frontmatter + full analysis)
│   └── 2024-ICRA-Tactile-Sensor-Fabrication-Zhang.md
├── Presentation_Summaries/           Extended slide-style analysis
│   └── 2024-ICRA-Tactile-Sensor-Fabrication-Zhang_summary.md
├── By_Research_Theme/               Theme-grouped link stubs (no PDF copies)
│   ├── Design_and_Fabrication/
│   └── ...
├── By_Application/                  Application-grouped link stubs
│   ├── Surgical_Robot/
│   ├── Tactile_Sensing/
│   └── ...
├── By_Year/                         Year-grouped link stubs
│   ├── 2024/
│   └── ...
├── Indexes/                         Auto-generated index notes
│   ├── Theme_Index_Design_and_Fabrication.md
│   ├── App_Index_Surgical_Robot.md
│   └── Year_Index_2024.md
└── Synthesis/                       (empty — for your own cross-paper notes)
```

### Papers/ — main note content

Each paper note contains:
- YAML frontmatter: title, authors, year, venue, DOI, themes, applications, confidence, tags
- Abstract excerpt
- Classification table
- Vault-relative PDF link: `[[01_Renamed.../Theme/Year/file.pdf|Open PDF]]`
- Notes section (editable)
- Related Papers section (editable)

### Presentation_Summaries/ — extended analysis

Each summary contains 11 sections extracted from the abstract:
1. One-Sentence Takeaway
2. Research Problem
3. Motivation
4. Key Contributions (bulleted)
5. Method
6. Experiments
7. Key Results
8. Strengths
9. Limitations
10. Future Work
11. Why It Matters (theme-based rationale)
12. Suggested Slide Summary (3-bullet slide deck)

## 03_New_Papers_Inbox

Used by incremental import mode.

```
03_New_Papers_Inbox/
├── To_Process/           Drop new PDFs here before running --mode incremental
├── Processed_Originals/  Source PDFs are copied here after successful import
└── Needs_Review/         Low-confidence new papers land here
```

## 90_Metadata

All logs and catalogs generated by each run.

| File | Content |
|---|---|
| `rename_log.csv` | Primary review file: original → renamed, vault paths, statuses |
| `papers_catalog.csv` | Full metadata for all papers (28 columns) |
| `papers_catalog.json` | Same as catalog in JSON format |
| `low_confidence_review.csv` | Papers below confidence threshold |
| `duplicate_candidates.csv` | Papers flagged as duplicates with match type |
| `run_log_<timestamp>.json` | Full audit trail per run |

### rename_log.csv columns

| Column | Description |
|---|---|
| `source_folder` | Subfolder within the raw PDFs root |
| `original_filename` | Original PDF filename (never changed) |
| `original_raw_path` | Full path to the source PDF |
| `new_filename` | Proposed canonical filename |
| `vault_relative_pdf_path` | Path inside the vault (used in Obsidian links) |
| `main_note_path` | Path to the generated Obsidian note |
| `application_note_paths` | Paths to application link-stub notes |
| `year_note_path` | Path to the year link-stub note |
| `title` | Extracted paper title |
| `first_author` | First author surname |
| `year` | Publication year |
| `venue` | Venue short code |
| `keywords` | Title keywords used in filename |
| `primary_theme` | Assigned research theme |
| `secondary_themes` | Additional themes with high keyword overlap |
| `applications` | Matched application tags |
| `confidence` | 0–1 extraction quality score |
| `is_low_confidence` | True if below threshold |
| `is_duplicate` | True if flagged as a duplicate |
| `copy_status` | DRY_RUN / COPIED / SKIPPED_EXISTS |
| `note_status` | WRITTEN / SKIPPED_EXISTS |
| `summary_status` | WRITTEN / SKIPPED_EXISTS |

## 99_Duplicates_or_Unclear

Papers whose canonical name collides with another paper (before suffix disambiguation). These are copied here for manual inspection.

## Vault-relative links

Obsidian notes always use vault-relative links. The vault root is `output_root` in `config.yaml`.

Example link in a note located at `02_Obsidian_Notes/Papers/`:
```
[[01_Renamed_PDFs_By_Research_Theme/Design_and_Fabrication/2024/2024-ICRA-Tactile-Zhang.pdf|Open PDF]]
```

Example relative link in a stub note located at `02_Obsidian_Notes/By_Application/Surgical_Robot/`:
```
[2024-ICRA-Tactile-Zhang.pdf](../../../01_Renamed_PDFs_By_Research_Theme/Design_and_Fabrication/2024/2024-ICRA-Tactile-Zhang.pdf)
```
